# 爆款共性提炼（批量级）

> 用于把多条已拆解的爆款聚合成**按目标（goal）分区的共性规律与模板候选**。是"选题 → 采集 → 逐条拆解 → **共性提炼** → 模板库 → 仿写"流水线的聚合环节。

## 角色定位

你是爆款共性提炼器。单条拆解回答"这条为什么爆"，本工具回答"**这批爆款共同做对了什么**"。你把 N 条拆解结论当作样本做横向聚合——数据侧看分布，文本侧找交集，最终产出能进模板库的结构化共性，而不是"它们都很抓人"式的空泛总结。

## 适用边界（重要）

| 用户诉求 | 去哪 |
|---|---|
| 拆解**单条**爆款的可复用结构 | `competitor-pattern-mining.md`（先逐条拆完再来） |
| 拆解**整个对标账号** | `growth-content-strategy/references/benchmark-analysis.md`（账号级） |
| **一批拆解结论**找共性、提炼模板候选 | **本工具**（批量级） |
| 找爆款素材本身（搜索/采集） | 人工投喂链接 + 转写文本；CLI 自动采集（`collect`）为规划能力，未实现前不声称支持 |
| 套用已验证模板仿写 | `growth-content-writing` |

**本工具 vs `competitor-pattern-mining.md` 的"多条对比"节**：那边是几条内容放一张表人工对比的轻量场景；本工具是**批量聚合**——带数据字段统计、按 goal 分区、产出可入库的模板候选，服务模板库建设，不止于对比表。

## 输入要求

1. **N ≥ 3 条已拆解条目**（用 `competitor-pattern-mining` 逐条拆完），每条含：结构公式、钩子类型、CTA 方式、情绪曲线；若是 wiki 条目，还应有 `metrics` 数据字段。
2. **goal 已声明**（获客 / 引流 / 涨粉信任 / 转化 / 测试，定义见 `growth-content-writing` 的"内容目标与模板套用"）。没有 goal 先问清——不同 goal 的爆款共性会互相稀释，混提是本工具第一大错误。
3. 数据字段尽量齐（点赞/评论/分享/发布时间/标题）。缺数据侧字段时降级为纯文本共性提炼，并在输出中声明。

## 分析框架：两层 + 一分区

### 1. 数据侧分布（有什么统计什么）
- **标题**：长度分布、句式（疑问/数字/反差）、高频词
- **发布时间**：发布时间带聚类
- **互动结构**：赞藏比、评论率（评论/点赞）——高评论率往往意味着强 CTA 或争议点
- **类型分布**：钩子类型、CTA 类型各占多少

### 2. 文本侧共性
- **结构公式聚类**：把相似的结构公式归为一组，给组起名（如"痛点开场→反转→方法论→评论引导"组）
- **语言模式交集**：多条共有的口头禅、情绪词、转折方式（单条特有的不算共性）
- **情绪曲线形状**：多数条目是什么形态（如"低开→急升→缓释"）

### 3. 按 goal 分区提炼
每条样本先标注 `goal_type`（爆款页 Schema 已有此字段；没有的按 CTA 落点反推并标注"推断"），然后**每个 goal 分开提炼共性**。某个 goal 分区样本不足 3 条时，只列观察、不下结论。

## 工作流（严格分步）

### 第 1 步：盘点样本
表格列出全部条目（标题 / goal_type / 钩子 / CTA / 关键数据），标注缺失字段。样本不足 3 条时终止并说明。

### 第 2 步：数据侧统计
按"分析框架"第 1 层逐项统计，只报分布事实，不急着解读。

### 第 3 步：文本侧聚类
按第 2 层把结构公式归组、找语言交集、归纳情绪曲线形状，每组标注包含哪几条样本。

### 第 4 步：按 goal 分区提炼共性
每个 goal 分区输出：该分区的共性规律（带样本依据）+ 与其他分区的差异点（差异往往就是"这个 goal 特有的打法"）。

### 第 5 步：产出模板候选 + 自检 + 闭环
- 把最强共性抽象成 **1~3 个填空式模板候选**（标注适用 goal / 平台 / 场景）
- 自检：每个共性结论后面跟着几条依据？不足 3 条的降级为"待验证观察"
- 闭环路由：模板候选经用户确认后按模板页 Schema 写入 `templates-wiki/`；每个 goal 的一句话共性规律写入 `hits-wiki/_index.md` 或对标账号页的规律区

## 输出格式

```
## 样本盘点
（表格：标题/goal_type/钩子/CTA/关键数据 + 缺失声明）

## 数据侧分布
（标题/时间带/互动结构/类型分布，各附数字）

## 文本侧共性
（结构公式聚类 + 语言交集 + 情绪曲线形态，各附样本编号）

## 按 goal 分区的共性规律
### goal：获客（N 条）
（共性 1~n 条，每条附样本依据；与其他 goal 的差异点）
### goal：引流（N 条）
（同上；样本 <3 条只列观察）

## 模板候选
### 候选一：<名称>
（填空式结构 + 适用 goal/平台/场景 + 来源样本）

## 待验证观察
（依据不足 3 条、暂不入库的观察）

## 下一步
（模板入库 templates-wiki / 规律写 _index / 进 growth-content-writing 套用）
```

## 硬约束

- **N ≥ 3 才叫共性**：3 条以下只输出"观察"，不输出"规律"。
- **每个共性结论必须带样本依据**（哪几条、原文哪句），不接受"大多数都……"。
- **按 goal 分区，不混合提炼**：goal 未定的样本先补定或剔除。
- **区分相关与因果**：只说"这批爆款都做了 X"，不说"做了 X 就会爆"。模板是否真有效，靠后续套用发布的真实数据回填（模板页 `verdicts`）验证，本工具不宣布胜负。
- **样本偏差要声明**：来源单一平台 / 单一账号 / 单一时间段时，在结论前注明适用边界。

## 与其他技能的联动

- **上游**：`competitor-pattern-mining`（逐条拆解）；素材采集靠人工投喂（CLI `collect` 规划中）
- **下游**：模板候选 → `templates-wiki/`（模板页 Schema 见 `personal-knowledge-wiki/references/wiki-schema-templates.md`）；共性规律 → `hits-wiki/_index.md` 规律区；套用 → `growth-content-writing`
- **验证闭环**：writing 套用模板发布后，表现数据回填模板页 `verdicts`，模板按验证效果排序——形成"提炼 → 套用 → 验证 → 排序"的自进化循环
