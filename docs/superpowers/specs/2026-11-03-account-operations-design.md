# 账号分析与自动运营系统：账号档案与诊断 MVP 设计

日期：2026-11-03
状态：待用户评审

## 背景

仓库已有七个平台的扫码登录、登录态检查、浏览器发布 CLI 和顺序编排，也有选题、创作、运营复盘等 Agent Skills。当前缺少系统化账号数据入口和账号级持久状态；创作包到发布任务、发布结果到复盘知识库的交接仍需人工完成。目标是让用户接入账号后，系统能基于证据分析账号，制定运营计划、生成待审核内容、经确认后发布并持续回流表现数据。

## 产品边界与阶段

自动运营分阶段交付，默认采用“先审核后发布”；自动发布必须在后续阶段按账号显式开启。

1. **MVP：账号档案与诊断**。本地维护账号档案和统一指标快照；先支持平台导出数据导入与手动录入。诊断结果区分数据事实、推断、建议，并指出数据覆盖和缺失。
2. **数据源扩展**。同一数据契约接入公开主页/作品信息采集，再逐平台接入已登录创作者后台指标采集。数据采集失败或平台不支持时，不覆盖旧快照，明确标示来源、时间和失败原因。
3. **运营与内容闭环**。结合账号档案、目标和表现数据制定选题/发布计划，生成平台适配内容包，进入待审状态；审核通过后调用现有发布器，保存发布回执和作品链接。
4. **效果回流与自动化**。导入或采集后续表现，更新单条/周期诊断和模板效果；账号达到用户设定条件后，用户可显式开启定时自动发布，并可随时关闭。

首份实现计划只覆盖 MVP，不假设平台已提供稳定 API，也不把提示词输出当作真实指标。后续阶段各自独立规格和验收。

## MVP 用户流程

1. 创建账号档案：平台、用户自定义别名、账号主页 URL、行业/品类、定位、目标受众、商业目标、内容方向、品牌语气、禁用表达和运营约束。登录凭据仍使用既有 cookie 流程；档案不保存 cookie 内容。
2. 导入某段时间的内容与账号指标，或用手动录入补齐。输入可包括 CSV/JSON；具体列名通过导入映射或固定模板标准化。
3. 校验数据并展示导入摘要：接收/拒绝条数、缺失字段、重复记录和时间范围。坏记录不会静默转换成零值。
4. 产出账号诊断：先展示已有事实和覆盖区间，再给定位/内容结构/发布节奏/互动表现的判断、置信限制和建议行动。缺少数据时明确提示，不伪造指标或结论。
5. 将档案、原始导入文件、标准化快照和诊断结果保存在本机，供后续运营 Skills 读取。

## 数据与存储

- 数据根目录复用 `SOCIAL_PUBLISH_DATA_DIR`，默认 `~/.social-publish-skills`。
- 账号目录按平台和安全化后的别名隔离，例如 `accounts/<platform>/<account>/`；每个账号维护 profile、导入源文件、规范化快照和分析报告。写入范围必须保持在账号目录内。
- 每个数据快照包含 `platform`、`account`、统计区间、采集时间、来源类型（`manual`/`import`/`public`/`creator_center`）、来源引用、指标值和内容记录。缺失值保持缺失，不用 0 代替。
- 同一条内容以平台内容 ID 为优先键；无 ID 时以来源 URL 及平台、发布时间组合识别。重新导入应可识别重复，保留原始输入以便追溯。
- `profile` 记录用户确认的账号定位和运营边界；分析报告记录使用的快照标识，确保建议可追溯。
- 本地账号档案与已有 cookie 只通过平台+别名关联。绝不读取或输出 cookie JSON 内容，也不复制凭据到档案。

## 组件边界

- **Account store**：负责档案、导入源、快照和报告的本地读写及路径边界。
- **Metric importer**：负责 CSV/JSON 解析、列映射、规范化、重复检测和逐行错误摘要；不负责解释运营结论。
- **Account analysis Skill**：读取档案与规范快照，输出有证据引用的诊断和下一步建议；不负责抓取平台页面或发布。
- **后续 source adapters**：公开数据和创作者后台各自适配同一快照契约；失败不破坏已有数据。
- **后续 approval/publish queue**：承接已审核内容包与现有 orchestrator；此 MVP 不改发布行为。

实现优先沿用现有 TypeScript、Node 文件系统和 Skills 的本地 Markdown 工作方式，不引入数据库、服务端、向量库或模型厂商依赖。

## 安全与失败处理

- 输入数据仅写入本机数据目录；不将指标或个人资料发送到新建远端服务。
- 所有路径从数据根目录解析并限制在账号目录；账号别名只接受安全文件名字符或映射成稳定安全目录名。
- 输入日期、数值、平台标识和必需字段有明确校验；保留原始文件，错误逐行可定位。
- 导入/分析失败不得删除或覆盖先前有效快照/报告。
- MVP 不读取 cookie 文件、不登录平台、不访问外部主页、不触发发布。

## 验收标准

1. 可为同一平台维护多个别名账号，并与不同平台的同名账号隔离。
2. 可按模板导入至少一种 CSV 或 JSON 指标数据；导入摘要能定位无效记录，且有效记录按统一 schema 保存。
3. 重复导入可识别重复内容，不产生重复快照条目；缺失指标保持为空。
4. 可创建/更新账号运营档案；分析输出引用所用数据区间和来源，并区分事实与推断。
5. 没有指标数据时只输出资料完整度与待补信息，不生成看似真实的账号表现结论。
6. 畸形数据、路径穿越别名或写入失败不损坏已有账号数据。
7. 现有平台登录与发布命令的契约不因 MVP 改变；MVP 本身不发帖。

## 待分阶段处理

- 公开主页数据和已登录后台采集均是最终目标，但需按平台分别验证页面可见字段、使用条款及稳定性，不承诺七个平台首批同时支持。
- 发布成功回执、逐账号自动发布开关、定时计划、暂停/重试、效果回流属于后续子项目，不纳入账号诊断 MVP。
- 不接入私信、评论自动回复、广告投放、账号密码保存或绕过平台风控。
